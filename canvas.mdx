The canvas gives you space to organize the project visually. It can contain running previews, editable design elements and service nodes. Moving a preview frame is different from changing the application's source code.

## Understand the selection

| Content | What you are working with |
| --- | --- |
| Web or mobile preview | An application running from project source |
| Frames, text and shapes | Editable design elements and layout |
| Images and uploaded assets | Visual material for the project |
| Service nodes and relationships | A view of project services and connections |

Use selection and contextual controls to inspect an object before changing it. Zoom and pan around the workspace. Keep related screens together so they are easy to inspect.

## Iterate on a design

Start with a frame and a small set of elements. Work on layout, spacing, type and color before adding decorative details. The agent can inspect and edit canvas elements; identify the frame precisely.

```text
Inspect the booking-form frame. Align the labels, make input spacing
consistent and keep the primary action visible on a narrow screen.
Preserve the field names and form behavior.
```

Changes to a design artifact need to be implemented and checked in the running app before they count as a completed application feature.

## Bring a Figma frame

The [Figma import tool](/figma) maps supported frame, text and shape elements into editable content. Inspect the result for unsupported elements or missing fonts. It does not promise a pixel-perfect conversion of every Figma feature.

## Work with services

Service nodes help explain how parts relate. Confirm status, credentials and configuration in [Services](/services); a connector drawn on a canvas does not replace application configuration or access checks.

Keep a recoverable checkpoint before major changes. Coordinate with [collaborators](/collaboration) when editing the same screen or frame.
