The **Services** panel shows the infrastructure attached to a project. Use it to inspect status, configure an individual service and understand which application depends on it.

## Choose the right service

| Service | Purpose | Next guide |
| --- | --- | --- |
| Application | Runs app or backend code | [Deployments](/deployments) |
| PostgreSQL | Stores structured application data | [Databases](/databases) |
| Redis | Cache, queues and temporary state | [Databases](/databases) |
| MinIO | S3-compatible object storage | [Object storage](/object-storage) |
| Custom service | A supported service template for a specific workload | Review the available catalog and configuration |

Availability depends on the service catalog and project configuration. A design element on the canvas is not proof that a corresponding running service exists.

## Add a service

Open **Services** in Studio and select **Add a service**. Choose an available type, give it a recognizable name and review its required configuration. Wait for the service status to indicate that it is ready before depending on it in the app.

Use the connection details supplied for that service. Configure the consuming application to use them and restart or redeploy it when required. Then test an actual request, database query or upload.

## Inspect and operate

A service's detail panel provides relevant controls such as **General**, **Environment**, **Domains**, **Deployments**, **Logs** and **Monitoring**. The available tabs depend on the service type.

Use logs to investigate startup failures and monitoring to understand resource use. Check the selected service before changing variables or restarting: an application's settings and a database's settings are not interchangeable.

## Plan persistence and capacity

Stateful services need a deliberate data plan. Keep schema migrations, backups, restore procedures and retention requirements in mind. Do not assume that creating a database also configures automatic backups or that adding application replicas safely scales a database.

<Warning>
Before deleting a service or changing persistent storage, identify the data it holds and verify a usable backup. Stopping an application and deleting a database are different operations.
</Warning>

Running production services can incur usage charges separately from the AI plan. Review [Usage and billing](/usage-and-billing), and use [Environment variables](/environment-variables) to keep connection secrets out of client code.
