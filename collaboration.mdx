Project collaboration lets an owner grant other IQX users access to a project. Choose the role that matches what each person needs to do, then coordinate work on shared source and services.

## Invite someone

Open the project's sharing or collaboration controls. Enter the intended collaborator's details, select the available editing or viewing role, and send the invitation. The invited person must accept and use the correct IQX account to access the project.

The owner manages invitations and access. Review the member list after acceptance, and remove access when a person no longer needs the project.

## Choose access deliberately

| Access | Intended use |
| --- | --- |
| Owner | Manage the project and its collaboration settings |
| Editor or collaborator | Work on the project within the permissions exposed by IQX |
| Viewer | Inspect shared work without running the editing agent |

Do not share your own account credentials as a substitute for an invitation. A link alone does not override project access checks.

## Plan limits

The current plan configuration includes the following project collaboration allowances:

| Plan | Collaborators | Viewers |
| --- | ---: | ---: |
| Free | Collaboration requires a paid plan | — |
| Pro | 5 | 5 |
| Business | 15 | 5 |
| Enterprise | Agreed configuration | Agreed configuration |

Check [Plans and credits](/plans-and-credits) and the in-product controls for the current allowance and any account-specific agreement.

## Shared credits

Collaboration access and shared billing are different. **Business and Enterprise** support the shared-credit option where enabled by the owner. Pro collaboration does not automatically provide a shared owner-funded credit pool.

Before starting an agent run, check the available credit context and agree who is funding the work. Viewing access does not grant permission to run the agent or spend shared credits.

## Coordinate changes

Assign clear areas of work, inspect current source before a large edit and avoid competing changes to the same files. Use [GitHub sync](/github-sync) when you need a reviewable source checkpoint. Coordinate database migrations, environment changes and production releases with the owner because they can affect other users.

If an invitation fails, check the invited account, acceptance status, membership limits and role. Include the project and visible error when requesting help through [Troubleshooting](/troubleshooting).
